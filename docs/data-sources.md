# 数据源与指标说明

本文档说明 Codex Usage Monitor 各栏位的数据来源、指标口径、状态灯和本地持久化规则。安装与日常配置请先阅读 [README](../README.md)。

## 1. 数据源总览

| 栏位 | 数据来源 | 所需凭据 |
| --- | --- | --- |
| 本会话 | 当前正在查看的 Codex 会话日志。 | 无需额外凭据。 |
| 官方订阅 | Codex Desktop 本机 app-server 返回账户周期与 Token 汇总；任务事件来自本机 `token_count`。 | 无需额外凭据。 |
| 重置预测 | 开源项目 [gussuri/codex-reset-observatory](https://github.com/gussuri/codex-reset-observatory) 公共接口返回的 12/24/48/72 小时社区统计概率。 | 无需凭据；非 OpenAI 官方数据。 |
| API 账户 | 第三方服务商的账户信息与请求日志接口。 | 账户访问令牌、数字用户 ID、Base URL。 |
| API Key | 第三方服务商为某个 Key 提供的额度或用量接口，由 Provider 映射响应字段。 | 对应 API Key。 |

API 账户与 API Key 是两种不同的数据来源：前者面向整个用户账户和请求日志，后者面向单个 Key 的额度信息。服务商的接口字段可能不同，可让 Codex 根据公开文档或脱敏响应适配。

“重置预测”每 5 分钟读取一次上游固定 HTTPS 公共接口，只发送无凭据 GET 请求，不上传本机用量、任务标识、对话内容或任何凭据。预测结果只用于显示，不参与自动续跑；上游将数据标记为过期时，该栏显示红灯并保留最近概率。

## 2. 官方订阅

官方数据来自本机 Codex app-server，不需要 API Key。监视器分别读取官方返回的 5 小时窗口和 7 天窗口；未返回对应窗口时显示 `--`，不会用其他周期冒充。

| 指标 | 含义 |
| --- | --- |
| 5小时剩余 | 官方 5 小时窗口的剩余百分比；展开面板同时显示该窗口的重置时间，折叠栏只显示百分数。 |
| 7天剩余 | 官方 7 天窗口的剩余百分比；展开面板同时显示该窗口的重置时间，折叠栏只显示百分数。 |
| 重置时间 | 优先显示 5 小时窗口重置时间；缺失时显示 7 天窗口时间，均缺失时显示 `--`。 |
| 今日 Token | 从本机当天 00:00 起，累计确认使用当前 ChatGPT 官方认证的每回合 `total_token_usage` 正增量。 |
| 近7天 Token | 以官方 `dailyUsageBuckets` 中本机日期的今天及前六个自然日汇总值为基准；官方值不变时叠加本机随后产生的官方订阅 Token，官方值变化时立即以新官方值重建基准。 |
| 累计 Token | 以最近一次官方累计值为基准，在官方值不变时叠加本机随后产生的官方订阅 Token。 |

本机实时累计只统计这台电脑上 Codex 已写入任务记录、并能确认由当前 ChatGPT 账户官方认证的用量。API、API Key 和无法确认来源的回合不计入官方订阅统计。程序只解析来源设置和 `token_count` 用量事件，不保存或上传对话正文。

### 今日 Token

“今日 Token”读取连续 `token_count` 快照中 `total_token_usage` 的正增量：

- 重复快照不会重复累计。
- fork 任务重放父任务历史时会去重。
- 不按模型、缓存、输出或 Fast 模式做费率折算。
- 本机没有有效计数时，不回退到官方日期桶。

### 累计 Token

“累计 Token”比较官方接口返回的完整整数，不比较格式化后的“万/亿”。官方值连续相同时，本机临时增量会继续更新；官方值发生变化时立即建立新检查点，并直接采用新的官方值。

如果官方只汇总了部分近期用量，显示值可能在官方检查点更新瞬间暂时变小。今日计数和累计临时增量保存在 `%LOCALAPPDATA%\CodexUsageMonitor\official-token-counter.json`。

## 3. 本会话

该栏位于“官方订阅”左侧，数据来自当前正在查看的 Codex 会话日志，不属于账户订阅汇总，也不做官方费率折算。

| 指标 | 含义 |
| --- | --- |
| 当前状态 | 由当前会话的结构化事件判断：`turn_context` 为“正在执行”，普通 `task_complete` 为“执行完成”，`usage_limit_exceeded` 为“额度用尽暂停”，`turn_aborted` 为“主动暂停”。 |
| 额度恢复续跑 | 位于“本会话”栏最底部，“当前状态”排在它上方。左侧复选框决定是否把续跑开关放进折叠监视栏；展开面板右侧开关和折叠栏开关都能启停同一功能，其下输入框配置恢复后发送的内容。 |
| 当前会话累计 Token | 当前会话从开始至今累计使用的原始 Token；每当 `total_token_usage.total_tokens` 快照发生变化时，加入对应的 `last_token_usage.total_tokens`，相同快照不重复计算。 |
| 上次回答消耗 Token | 最近一次收到 `task_complete` 的回答中，各个非重复用量快照对应的 `last_token_usage.total_tokens` 之和。 |
| 缓存命中率 | 当前会话累计 `cached_input_tokens ÷ input_tokens`；只统计输入 Token，结果最多显示一位小数。 |
| 自动压缩上下文次数 | 当前会话日志中自动压缩后的上下文窗口编号；读取 `compacted.payload.window_number`，不重复计算同次压缩产生的 `context_compacted` 通知。 |

“上次回答”从用户发送一条消息开始，到该轮 `task_complete` 为止。回答过程中的工具调用、重试和多步推理都会计入；当前回答仍在生成时，界面继续显示最近一次已完成回答，不会混入尚未完成的当前轮。

“当前状态”只使用日志事件，不读取或匹配界面文案。非额度类错误仍归入“执行完成”，因为它表示本轮已经终止；没有识别到当前会话或有效事件时显示 `--`。它和“额度恢复续跑”固定排在本会话数据项底部。

Codex 可能对 `total_token_usage.total_tokens` 做小幅回调或重新核算。该数值变化只用于识别“是否出现新的用量快照”，实际新增量取同一事件的 `last_token_usage.total_tokens`；因此小幅回调不会被误当成整段新用量，相同累计快照的重复通知也不会重复计算。

缓存命中率与会话累计使用相同的非重复快照边界，并累加每个有效 `last_token_usage` 的输入 Token 与缓存输入 Token。没有有效输入 Token 时显示 `--`，不会把输出 Token 或推理 Token 计入分母。

## 4. API 账户

当前账户适配器面向“数字用户 ID + Access Token + 账户信息接口 + 请求日志接口”这一类协议，内置实现兼容 CCTQ 风格的 `/api/user/self` 和 `/api/log/self`。这只是当前兼容协议，不代表 API Key 功能绑定特定供应商。

| 指标 | 含义 |
| --- | --- |
| 账户余额 | 账户接口返回的 `quota`，按服务商额度单位换算。 |
| 累计已用额度 | 账户接口返回的 `used_quota`，不是本地日志估算值。 |
| 今日 Token | 从本机当天 00:00 起，对新请求的输入与输出 Token 做指纹去重后累加。 |
| 累计 Token | 用户设置的初始值，加上基准检查点之后发现的新请求 Token。 |
| 上次消耗额度 | 最新一条日志的额度消耗，保留三位小数。 |
| 上次响应模型 | 最新一条日志的模型名称。 |
| 上次请求时间 | 最新一条日志时间，按本机时区显示。 |
| 上次响应耗时 | 最新一条日志的响应耗时，以毫秒显示。 |

API 账户每轮先刷新日志第一页。如果第一页尚未覆盖上次检查点，会继续读取可见分页，并按稳定请求 ID 或请求指纹去重；覆盖检查点后立即停止。任何必要分页失败时，界面保留上一次账本值，不使用残缺页面更新累计与今日 Token。

第三方日志接口通常只返回有限页数，因此需要累计 Token 基准。请填写当前真实完整整数；如果不知道就填 `0`，后续只按监视器可见的新日志累加。

API 账户账本保存在 `%LOCALAPPDATA%\CodexUsageMonitor\account-token-counter.json`。本机日期跨过 00:00 后只清零今日计数，累计值继续保留。

## 5. API Key

API Key 使用声明式 Provider 配置。首次在面板中保存时，界面会把服务地址、用量路径、认证头和响应字段映射交给本机后台验证；密钥由 DPAPI 单独加密，不会写入 Provider JSON。

| 指标 | 含义 |
| --- | --- |
| 已用额度 | Provider `response.used` 映射到的已用金额或点数。 |
| 限额 | Provider `response.limit` 映射到的上限；没有上限或 `unlimited` 为真时显示“不限”。 |
| 到期时间 | Provider `response.expiresAt` 映射到的到期日；没有到期信息时显示“永久”。 |
| 请求状态 | 最近一次 API Key 用量请求的状态。 |

若响应格式不同，优先修改本地 `*.local.json` 的 selectors。如果接口需要特殊分页、签名或响应转换，应先检查安全边界，再修改客户端并补充测试。配置校验会拒绝 URL 内凭据、跨域路径和试图嵌入密钥的字段。

Provider 示例：

```powershell
Copy-Item .\config\providers\custom.example.json .\config\providers\my-provider.local.json
pwsh -NoProfile -File .\scripts\configure-api-provider.ps1 -ConfigPath .\config\providers\my-provider.local.json -FromClipboard
```

## 6. 状态指示灯

指示灯只表示该栏最近一次用量请求，不代表 Codex 对话或模型服务状态。

| 颜色 | 状态 | 说明 |
| --- | --- | --- |
| 亮绿色 | 已同步 | 最近请求成功，显示最新数据。 |
| 亮黄色 | 正在同步 | 正在请求；已有数据继续保留。 |
| 亮红色 | 数据过期 | 本轮失败，但有上一次成功数据；数值继续保留。 |
| 灰色 | 请求失败或暂无数据 | 尚未取得可用数据、未配置或请求失败。 |

API Key 接口返回 `HTTP 429` 时，该栏显示“请求受限”并保留上一次成功数据。监视器从 60 秒开始逐步延长重试间隔，最长 5 分钟；成功后恢复 60 秒刷新。

折叠监视栏不显示指示灯。展开面板底部的刷新倒计时表示网络接口同步时间；符合条件的本机 Token 事件由独立增量扫描器更新，活动期间通常约 2 秒反映到界面。

## 7. Token 显示单位

- 中文界面少于 `10,000` 时显示完整数值。
- 达到 `10,000` 后以整数“万”显示。
- 达到 `100,000,000` 后以两位小数“亿”显示。
- English UI 使用常见的 `K`、`M`、`B` 缩写。

展开面板与折叠监视栏使用相同单位规则。

## 8. 显示开关

- **极简模式**：隐藏指标名称，只显示数值与单位；最多选择 14 项，选中 9 项及以上时使用双行压缩布局。
- **倒计时可视化**：在折叠监视栏最左侧显示与文字同色的圆形表盘，绿色指针每 60 秒顺时针旋转一圈。
- **设置入口**：全局选项和品牌信息位于“官方订阅”栏底部；点击“设置”才展开两列三行的六个选项。新安装默认隐藏 API 账户和 API Key 两栏，可用“API 栏”开关恢复；“重置预测栏”可独立显示或隐藏。
- **显示顺序**：折叠监视栏严格按指标勾选先后从左到右排列；取消后再次勾选会移动到末尾，顺序随其他界面设置一起持久化。
- **English UI**：切换中英文界面，并同步使用 `K`、`M`、`B` 英文单位。
- **自动更新**：开启后，运行中的监视器最多每 24 小时无凭据检查一次本项目的 GitHub Release。仅接受正式版本及名称严格匹配的 Windows ZIP，并在下载后核对 GitHub 提供的 SHA-256 摘要；校验通过才安装并热替换监视器后台，不会重启 Codex。任何步骤失败都会保留当前版本，并在下个周期重试。
- **额度恢复续跑**：位于“本会话”栏，默认关闭；开关和发送内容按任务 ID 独立保存。开启后，只有该任务出现 `usage_limit_exceeded`、错误重置时间已经到达且对应官方周期剩余百分数大于 `0%` 时，才通过 Codex Desktop 渲染器内的请求客户端按原任务 ID 调用 `thread/resume` 和 `turn/start`。续跑回合绕过原生排队消息，既不填写可见输入框，也不删除或改写已有队列；同一额度事件使用稳定的客户端消息 ID，最多成功提交一次。
